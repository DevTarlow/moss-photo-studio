# Prompt lab

The lab in `scripts/lab/` calls the **real Meta Muse API** with the app's own prompt builders and Muse client. It exists to calibrate the category recipes against real photos, not to run in the test suite.

- It is never run by `npm test`, Playwright, or CI.
- Every returned image costs the app's rate (`CENTS_PER_IMAGE`, $0.01).
- Generated output lives in `lab/`, which is gitignored.
- The app itself still stores its key in the system keyring. The lab's key is read from `.env` only.

## Setup

1. Copy `.env.example` to `.env` (the first setup already created it with an empty value).
2. Paste a Meta Muse key after `MOSS_LAB_MUSE_KEY=`.
3. Keep `.env` private. It is gitignored and must never be committed.

```dotenv
MOSS_LAB_MUSE_KEY=LLM|...
MOSS_LAB_MAX_CENTS=300
```

`MOSS_LAB_MAX_CENTS` is a hard stop across all lab runs recorded in `lab/spend.json`, not a per-run limit. Raise it deliberately or pass `--max-cents`.

## Commands

```bash
npm run lab -- plan   --category clothing
npm run lab -- plan   --all
npm run lab -- set    --category clothing --source shirt.jpg --yes
npm run lab -- set    --category clothing --source shirt.jpg --limit 3 --yes
npm run lab -- set    --category food --source lab/sources/food.webp --shots detail,lifestyle --yes
npm run lab -- edit   --template kitchen-table --source shirt.jpg --yes
npm run lab -- create --text "A ceramic mug on a white background" --yes
npm run lab -- sources --yes
npm run lab -- people  [--ids maya,omar] [--force] --yes
npm run lab -- looks   [--ids maya,omar] [--looks front,seated] [--force] --yes
npm run lab -- sweep   --yes
npm run lab -- resume  lab/runs/2026-11-09-140000-set-clothing --yes
```

Common options:

| Option | Meaning |
| --- | --- |
| `--shots hero,onmodel` | Only the named shot types from the recipe. |
| `--limit 1` | Enable the first N shots, matching the onboarding presets. |
| `--shape`, `--format` | Override the source-derived shape and the WebP default. |
| `--palette "#112233,#445566"` | Test the brand colour clause. |
| `--person maya` | Bundled person for on-person edits/sets. |
| `--look seated` | One of the bundled person's studio looks, for on-person edits, creates and the `looks` batch. |
| `--directions-file <json>` | Lab-only direction overrides keyed by shot type. |
| `--gift-clause-file <txt>` | Lab-only gift clause override. |
| `--max-cents 300` | Override the ledger cap. |
| `--concurrency 2` | In-flight requests per run, 1 to 4. |

`plan` makes no network request and costs nothing. `--yes` is required before any paid command. Without it the lab prints the planned count and cost and exits.

## Prompt parity

The lab does not copy prompt strings. It loads the shipping modules through Vite SSR:

- `src/shared/prompts/recipes.ts` — category rosters, directions, gift clauses.
- `src/shared/plans.ts` — plan creation and shot order.
- `src/shared/prompts/setPlan.ts` — the same prompt specs the job queue sends.
- `src/main/muse/client.ts` — the same model, size, format, retry and 429 behaviour.
- `src/main/media/import.ts` — the same source normalisation (2048px WebP, EXIF stripped).

The job queue and the lab both call `planSetPrompts`, so a calibration run tests exactly what ships.

## Sources

Put a real product photo at `lab/sources/<category>.jpg` (or `.jpeg`, `.png`, `.webp`) to use it for that category. `npm run lab -- set` takes any path.

`lab/sources/clothing.jpg` is a copy of the owner's real shirt photo. The other categories use clean stand-in product photos generated by `npm run lab -- sources` (10 images, $0.10) because no owner photos were provided. These stand-ins are marked `"source": "synthetic"` in `lab/sources/manifest.json`, and the calibration report notes the limitation. Drop real photos into the same folder to replace them.

## People pack

`npm run lab -- people` generates the bundled reference people from `scripts/lab/people-pack.mjs` (24 images, $0.24) into `lab/people/`. Each person gets a full-body `640x960` WebP and a `512x512` portrait cropped from the top of the same image. `--ids` regenerates only some people; `--force` replaces images that already exist. Review the run's `sheet.webp` and the individual portraits, then copy the approved files into `resources/people/` and keep `src/shared/people.ts` and the pack in sync. The prompts ask for candid, happy, full-body, head-to-toe shots with one person, simple settings and no text or logos.

## Person looks

`npm run lab -- looks` generates the four alternate studio looks for every bundled person from `scripts/lab/person-looks.mjs` (96 images, $0.96) into `lab/looks/`. Each request edits the person's bundled `resources/people/<id>.webp` with a prompt for `front`, `angle`, `full` or `seated`; the result is resized to `640x960` WebP and written as `lab/looks/<id>-<look>.webp`. `--ids` and `--looks` narrow the batch; `--force` regenerates images that already exist. The cap needs headroom: the full batch moves the ledger by 96 cents, so raise the local cap or pass `--max-cents 400`. Start with a three-person pilot (`--ids maya,omar,june`), review identity, framing and the studio background on the run's `sheet.webp`, then run the rest. Copy only approved files into `resources/people/`; `src/shared/people.ts` names the keys and labels and the asset test checks that every bundled person has all four. Use `--person <id> --look <key>` on `create` or `edit` to try a look prompt by itself.

## Output

```
lab/
  sources/<category>.webp        # owner photos or generated stand-ins
  sources/manifest.json          # prompts and provenance for stand-ins
  people/<id>.webp               # reviewed full-body person reference
  people/<id>-portrait.webp      # square portrait cropped from it
  people/manifest.json           # prompts and provenance for people
  looks/<id>-<look>.webp         # reviewed alternate studio look, 640x960
  looks/manifest.json            # prompts and provenance for looks
  spend.json                     # cumulative actual returned-image cost
  plans/<stamp>-<label>.json     # free prompt plans
  runs/<stamp>-<command>-<slug>/
    manifest.json                # prompts, revised prompts, IDs, usage, cost, hashes
    source/working.webp          # exact normalised source
    images/<group>/*.webp        # returned images
    thumbs/<group>/*.webp
    index.html                   # offline contact sheet with prompts
    sheet.webp                   # one montage for quick review
    review.md                    # per-shot verdict template
```

A `sweep` creates a parent `runs/<stamp>-sweep/` with one full run folder per category and a top-level `index.html` linking them.

## Review workflow

For each image, write a verdict in `review.md`:

1. **Product fidelity** — same item, colour, pattern, proportions and label text; no invented variants or duplicated products.
2. **Shot intent** — hero is a clean listing shot; on-person is worn; detail shows texture; scale reads; flat lay is styled; gift looks gifted.
3. **Category fit** — the scene and props belong to the category.
4. **Listing usability** — clean framing, nothing cut off, no stray text or watermarks.
5. **Guard compliance** — reference images preserved, the right person, the gift rule respected.

Verdicts are `keep`, `fix` or `drop`. Use `--directions-file` to try a fix before changing `src/shared/prompts/recipes.ts`.

## Safety

- The lab prints only the last four characters of the key.
- The key is never written to a manifest, filename or log.
- A timeout is recorded with uncertain billing and is not retried automatically; use `resume` after checking.
- Refusals and other failures cost $0.
- Do not run the lab in CI or against a release account without the owner's approval.
